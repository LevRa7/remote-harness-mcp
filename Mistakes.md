# Mistakes.md — Журнал ошибок и архитектурных предохранителей (Live USB & Rescue)

## 1. Зависание воркера MCP на сбойных секторах диска (D-State I/O Hang)
- **Причина:** Вызов `smartctl`, `blkid`, `parted` или `mount` на физически сыплющемся SSD/HDD переводит дочерний процесс в неперебиваемый сон (`TASK_UNINTERRUPTIBLE` / `D`-state) при ожидании ответа контроллера диска.
- **Решение:**
  1. Перед обращением к блочному устройству проверять хвост `dmesg` на свежие `I/O error` / `blk_update_request` / `nvme: I/O Cmd` для данного девайса.
  2. Запускать внешние утилиты с жестким `timeout` в отдельной группе процессов (`start_new_session=True`), а при истечении таймаута возвращать `{"available": False, "reason": "device_io_timeout_d_state_risk"}` без блокировки основного цикла агента.

## 2. Повреждение файловой системы при автоматическом воспроизведении журнала (Journal Replay)
- **Причина:** Обычный `mount -o ro /dev/nvme0n1p2 /mnt` на `ext4` или `xfs` всё равно пытается воспроизвести журнал транзакций на диск, что при нестабильных ячейках памяти приводит к разрушению суперблока и таблицы инодов.
- **Решение:** В инструменте `rescue_action(action="mount_safe")` для `ext4` и `xfs` принудительно подставлять опции `ro,noload` (или `ro,norecovery`), а для `ntfs` — `ro,noatime`. Монтирование в `rw` разрешается только при явном флаге `writable=True` после успешного SMART-теста.

## 3. Обрыв туннеля при диагностике сети (Active Uplink Suicide)
- **Причина:** Во время восстановления сетевых настроек агент может перезапустить `NetworkManager` или сбросить интерфейс, через который сам держит WebSocket/HTTP-туннель с координатором.
- **Решение:** Перед любым сетевым действием вычислять интерфейс маршрута по умолчанию (`ip route show default`). Этот интерфейс помечается как `protected_uplink` и блокируется для модификации из MCP без отложенного таймера отката.

## 4. Переполнение RAM-диска (OverlayFS OOM) при снятии образов и дампов
- **Причина:** В режиме Live USB корень `/` находится в `tmpfs` (ОЗУ). Если `ddrescue`, `e2image` или дамп логов сохраняются в `/tmp` или `/root`, оперативная память исчерпывается за секунды, вызывая `Kernel Panic`.
- **Решение:** В `rescue_action(action="ddrescue_start")` проверять путь назначения через `df -T`. Если целевой путь лежит на `tmpfs` / `overlay`, инструмент возвращает отказ и требует указать примонтированный внешний накопитель или `scratch`-раздел флешки.
