# Easy MCP против Remote Harness MCP (Antigravity-mash)

Сравнение двух MCP-серверов, которые дают веб-модели (Claude Web, ChatGPT, Gemini) доступ к локальной машине:

- **Easy MCP** — https://github.com/mrkaylabs/easy-mcp (JavaScript, 2 файла кода, 98 ★, 26 форков, создан 2026-11-20, MIT).
- **Remote Harness MCP** — этот репозиторий (Python, 36 модулей в core/, 85 файлов тестов, 8 ★, MIT, версия 0.7.0-rc1-alpha).

Замеры сделаны на одной машине: оба сервера подняты рядом и опрошены по HTTP на loopback, один и тот же каталог-корпус (540 файлов, 15,7 МБ — копия core/, tests/, docs/, tools/, skills/, bin/, npm/, templates/, .github/ этого репозитория).
Окружение: Windows 11, Node 22.12.0, Python 3.12.3, медиана из 3–11 повторов.

---

## 1. Что каждый проект собой представляет

| | Easy MCP | Remote Harness MCP |
| :--- | :--- | :--- |
| Язык и размер | JavaScript, 2 файла: server.js 92 КБ / 2055 строк + запускатор 7,7 КБ | Python, 36 модулей core/ ≈ 18 000 строк + 85 файлов тестов ≈ 16 600 строк |
| Зависимости | ноль (только stdlib Node 18+) | stdlib Python; опционально PyMuPDF/ffmpeg/tesseract; для установки — Tailscale |
| Что открывает | один локальный каталог проекта | машину (файлы, оболочку, экран, устройства) и, в режиме шлюза, несколько узлов |
| Адресация | один сервер = один каталог = один адрес | узел = адрес; несколько узлов = несколько адресов или шлюз |
| Инструментов в tools/list | 17 (18 в README) | 33 |
| Тесты / CI | нет ни тестов, ни CI | 85 тестов, 3 workflow (ci, release, team-coverage) |
| Возраст | 3 дня на момент замера | с 2026-09-06, версия 0.7.0-rc1-alpha |

Easy MCP — это «MCP-сервер в одном файле + туннель + дашборд». Remote Harness MCP — это «агент на машине»: инструменты, режимы доступа, шары, таймеры, автообновление, ветка устройства и шлюз для нескольких узлов.

## 2. Использование: установка и первый запуск

**Easy MCP.** Одна команда npx -y <tar.gz с GitHub> в нужном каталоге: поднимается сервер на 127.0.0.1:9494, открывается дашборд, туннель публикует адрес. Ссылку вставляют в коннектор Claude/ChatGPT/Gemini, токен уже внутри. Порог входа — минуты, права администратора не нужны. Есть OAuth 2.1 (discovery, /oauth/register, /oauth/authorize, /oauth/token) — это то, что требует часть веб-клиентов.

**Remote Harness MCP.** Установщик install-gui.cmd (мастер) или install.ps1 -Mode standalone -Funnel / ./install.sh --mode=funnel: ставит Tailscale, поднимает Funnel на 443, генерирует MESH_TOKEN, регистрирует автозапуск (задача SYSTEM или rhm-node.vbs), проверяет публичный адрес и печатает готовую ссылку https://<узел>.<tailnet>.ts.net/sse?token=… . Плюс консольное меню rhm, веб-настройки, автообновление. Порог входа выше: права, tailnet, ACL для Funnel, иногда UAC.

Разница по духу: Easy MCP сознательно **ничего не администрирует** и работает как «синхронизатор файлов», а Remote Harness MCP — полноценный агент с автозапуском и самообновлением.

## 3. Покрытие сценариев

| Сценарий | Easy MCP | Remote Harness MCP |
| :--- | :--- | :--- |
| Чтение файла целиком | read_file (до 10 МБ, отказ на бинарнике) | read_file (без лимита размера, пагинация max_chars/cursor) |
| **Чтение конкретных строк** | нет: только целиком | read_file(start_line, end_line) плюс cursor |
| Пакетное чтение | read_files (несколько файлов целиком) | batch_read: до 16 операций, у каждой свой диапазон строк |
| **Поиск файлов по имени** | нет (только list_directory, один уровень) | glob_find: **/*.py, глубина, бюджет времени, обрезка каталогов, SQLite-FTS индекс |
| **Поиск по содержимому** | search_files: подстрока, без regex, без фильтра по имени, 200 хитов | grep_search: regex или литерал, glob, ignore_case, context, limit, max_depth, time_budget_ms |
| Запись файла | write_file, write_files | write_file (атомарно: tmp + os.replace, sha256 в ответе), batch_edit с dry_run |
| Правка фрагмента | edit_file (только уникальный фрагмент, без replace_all) | edit_file (replace_all, expected_sha256 от гонок) |
| Оболочка | execute_command — **выключена по умолчанию**, включается в дашборде | bash_exec + run_script (python/powershell/bash/cmd без проблем с квотингом) |
| Фоновые задачи | start_job, job_status, stop_job, list_jobs | run_job, job_output (wait до 20 с, курсор), job_kill, job_list |
| Таймеры / cron | нет | schedule (once / every / at HH:MM + продолжение) |
| **Шеринг файлов людям** | нет: публикуется только MCP-эндпоинт | share_file, serve_dir — публичные HTTPS-ссылки со случайным сегментом; share_list, unshare |
| Git | git_status, git_diff (защита от исполнения через конфиг git) | только через bash_exec |
| Загрузка URL | fetch_url (только https, блок приватных адресов и DNS-ответов, 5 редиректов, 300 КБ) | нет |
| Медиа | нет | read_media (картинка/PDF/аудио/видеокадры/OCR), screen_capture |
| Ветка устройства | нет | device_info, device_control, device_capture, device_messages (Android/Termux) |
| Управление узлом | set_project (сменить каталог) | node_control (read_only/full, пауза, cd, Docker-изоляция, блокировка удалённого управления) |
| Самообновление | нет (npx кеш, обновление руками) | mesh_update (проверка релиза, SHA-256, откат, рестарт) |
| Долгая цель чата | нет | goal (переживает реконнект и новую сессию) |

## 4. Скорость: что показали замеры

Все цифры — медиана времени ответа сервера по loopback, без учёта сети и без учёта времени модели.

| Операция | Remote Harness MCP | Easy MCP | Что это значит |
| :--- | :--- | :--- | :--- |
| grep «def » с фильтром *.py | **7,3 мс**, 30,6 КБ, 200 совпадений | 70,4 мс, 13,5 КБ | мой в 9,6 раза быстрее: останавливается на лимите и фильтрует по имени файла |
| grep «frozenset», полный проход | 130,7 мс, 5,0 КБ | **67,8 мс**, 2,4 КБ | мой в 1,9 раза медленнее: Python на построчном regex против Node includes |
| glob **/*.py | 56,7 мс, 13,2 КБ (около 300 путей) | инструмента нет; list_directory 15,9 мс, 0,25 КБ, один уровень | сценарий закрыт только у меня |
| read_file целиком (462 строки) | 5–15 мс, 19,0 КБ | **1,1–1,7 мс**, 18,8 КБ | оба укладываются в единицы миллисекунд |
| read_file строки 300–400 | 3–15 мс, **4,3 КБ** | только целиком: 1,7 мс, **18,8 КБ** | у Easy диапазона нет: либо весь файл, либо ничего |
| write_file 5 КБ | **4,3 мс** (+sha256, атомарная запись) | 12,8 мс | мой быстрее и безопаснее |
| edit_file уникального фрагмента | 5,3 мс (вместе с записью 15,9 мс) | **1,4 мс** (вместе с записью 1,7 мс) | у Easy быстрее, но без replace_all и без проверки sha256 |
| 8 чтений диапазонов | **1 вызов**, 31,5 мс, 17,8 КБ | 8 вызовов, 61,6 мс, 150,5 КБ | в 8 раз больше round-trip-ов и в 8,4 раза больше контекста у Easy |
| tools/list | 33,5 КБ, 33 инструмента | **4,9 КБ**, 17 инструментов | описания моего сервера дороже в контексте каждой сессии |
| Пустой вызов (оверхед протокола) | около 16 мс | около 15 мс | одинаково |
| Память процесса (RSS) | около 50,6 МБ | около 56,8 МБ | одинаково |

### Как это читать

1. **Абсолютные миллисекунды ничего не решают.** Разница в 10–60 мс исчезает на фоне одного шага модели (секунды). Реальную скорость задачи определяют два других числа: **сколько round-trip-ов** и **сколько токенов** вернул инструмент.
2. По round-trip-ам мой выигрывает там, где есть пакетность: batch_read и batch_edit укладывают 8–16 операций в один вызов (в замере — 1 вызов вместо 8), а у Easy каждая операция — отдельный шаг модели.
3. По токенам мой выигрывает на чтении (диапазон строк: 4,3 КБ против 18,8 КБ), но проигрывает на грепе: JSON с абсолютными путями даёт 30,6 КБ против 13,5 КБ у плоского текста Easy.
4. По сырой скорости одного полного прохода по каталогу Easy быстрее (Node + includes), но платит за это блокировкой event loop: search_files читает файлы синхронно, и дашборд в это время не отвечает.

## 5. Плюсы и минусы

### Easy MCP — плюсы

- **Порог входа**: одна команда, ноль зависимостей, один файл, дашборд. Никаких прав администратора и никакого VPS.
- **Правильная модель безопасности для своего масштаба**: токен обязателен, bind только на loopback, тюрьма каталога с разрешением симлинков, оболочка **выключена по умолчанию**, блокировка записи в .git/hooks и .git/config, fetch_url с защитой от SSRF, отказ на бинарниках, лимит 10 МБ на чтение.
- **OAuth 2.1** (register, authorize, token) плюс Streamable HTTP и legacy SSE — подключается туда, где нужен именно OAuth-коннектор.
- **Экономия контекста**: относительные пути, плоский текст, короткие ответы (4,9 КБ на весь список инструментов).
- **Стабильная ссылка** в режиме Tailscale Funnel, бесплатный Cloudflare quick tunnel без аккаунта.
- **Презентация**: короткий и честный README с моделью угроз; видно, что автор думал о том, как это ломают.

### Easy MCP — минусы

- **Нет чтения диапазона строк** — главный практический минус: файл на 2000 строк всегда приходит целиком.
- **Поиск по содержимому слабый**: только подстрока, регистрозависимо, без regex, без фильтра по имени файла, максимум 200 хитов, обход синхронный, до 5000 файлов и 2 МБ на файл.
- **Нет поиска по имени файла** (glob), нет индекса, нет бюджета времени: на большом дереве запрос просто длинный.
- **Нет шеринга файлов и каталогов** — отдать человеку ссылку на файл нельзя, только MCP-эндпоинт.
- **Один каталог, одна машина** — нет мультиузловости, нет ветки устройства (телефон), нет таймеров и cron, нет автообновления (npx кеширует копию навсегда).
- **edit_file без replace_all и без проверки sha256** — повторяющийся фрагмент править нечем, от гонок защиты нет.
- **Нет пагинации**: 300 КБ на вывод команды, 10 МБ на файл — большой лог читать нечем, кроме execute_command с tail.
- **Зрелость**: 3 дня, 2 файла, ни одного теста, ни CI. Ломающие изменения придётся ловить в бою.

### Remote Harness MCP — плюсы

- **Инструментарий под реальные задачи**: диапазоны строк, glob, regex-грep с фильтрами и бюджетом времени, пакетные чтение и правка, run_script на четырёх языках, FTS5-индекс для мгновенного glob.
- **Экономия круглых поездок и контекста**: batch_read и batch_edit — до 16 операций за вызов, dry_run для проверки правок, курсоры вместо обрезки.
- **Шеринг для людей**: share_file и serve_dir дают публичный HTTPS-адрес со случайным сегментом — скриншот, PDF, собранный сайт уходят человеку ссылкой, а не только модели.
- **Мультиузельность и ветка устройства**: телефон на Android/Termux читается и управляется теми же инструментами (батарея, датчики, камера, SMS под отдельными ключами).
- **Управляемость**: режимы read_only/full, пауза, cd, Docker/Podman-изоляция, блокировка удалённого управления, журнал вызовов, автообновление с SHA-256 и откатом.
- **Надёжность записи**: атомарная запись, expected_sha256 в edit_file, отказы с внятным текстом вместо тихой порчи файла.
- **Инженерная дисциплина**: 85 файлов тестов, 3 CI-workflow, аннотации MCP (readOnlyHint / destructiveHint) на каждый инструмент, чтобы клиент спрашивал подтверждение только там, где надо.

### Remote Harness MCP — минусы

- **Тяжёлая установка**: Tailscale, права, автозапуск, ACL для Funnel. Для задачи «просто дать модели папку» это перебор.
- **33 инструмента = 33,5 КБ описаний** в контексте каждой сессии (примерно 8–9 тыс. токенов) против 4,9 КБ у Easy; модель дольше выбирает инструмент.
- **Многословные ответы**: JSON с абсолютными путями Windows — на грепе это в 2,2 раза дороже по токенам, чем у Easy.
- **read_file не отбивает бинарники**: на GIF в замере вернул 51 КБ мусора (Easy в этой же ситуации честно ответил Binary file). Лечится read_media, но по умолчанию модель пойдёт в read_file.
- **Полный проход по каталогу медленнее** (130,7 мс против 67,8 мс) — Python проигрывает Node на построчном поиске.
- **Нет fetch_url и git-инструментов** — документацию не скачать через узел, git diff только руками через bash_exec.
- **Документация расходится с кодом**: README говорит 28 инструментов на узле и 30 через шлюз, tools/list отдаёт 33.
- **Поверхность атаки шире**: оболочка доступна сразу (в Easy выключена по умолчанию), плюс шары, устройство, автообновление.
- **Эксплуатационные мелочи**: два процесса могут одновременно слушать один порт (наткнулся на это при замерах — Windows разрешает bind), 543 КБ журнала вызовов уже накопилось.

## 6. Итог: кто для чего

**Easy MCP** — когда нужно за пять минут дать веб-модели папку проекта и не думать об администрировании: правки кода, просмотр файлов, запуск тестов, обзор проекта. Идеален для одного разработчика на одной машине, особенно если клиент требует OAuth-коннектор.

**Remote Harness MCP** — когда нужен агент на машине, а не синхронизатор папки: длинные задачи с фоновыми процессами и таймерами, точечное чтение больших файлов, поиск по коду с фильтрами, несколько узлов, телефон как узел, ссылки на файлы для людей, изоляция и режим только-чтение.

Практический вывод: это не конкуренты, а два разных класса. Easy MCP выигрывает по входному барьеру, компактности и аккуратности мелочей безопасности; Remote Harness MCP — по глубине инструментария, пакетности, шерингу и управляемости.

## 7. Что стоит подтянуть в моём проекте

1. Отбивать бинарные файлы в read_file (проверка на NUL-байт, как в Easy) с подсказкой использовать read_media.
2. Компактный режим вывода для grep_search: относительные пути и плоский текст (path:line: text) — экономит половину токенов.
3. Урезать tools/list: короткие описания и разнесение редких инструментов (device-*, mesh_update) в подключаемый набор — 33,5 КБ на каждую сессию дорого.
4. Добавить fetch_url с защитой от SSRF и git_status / git_diff без оболочки.
5. Закрыть расхождение README и tools/list; проверить, почему два процесса могут занять один порт.
6. Быстрый путь для мелких вызовов: около 15 мс на вызов при пустом ответе — это журнал и санитизация на каждом запросе; можно вынести в асинхронную запись.

## Приложение: как воспроизвести замеры

```
node _scratch/easy-mcp/server.js _scratch/corpus --no-tunnel --token benchtok --enable-shell --port 9599
$env:MESH_TOKEN=benchtok; python -m core.server --host 127.0.0.1 --port 8601 --token benchtok
python _scratch/bench.py     # основной прогон
python _scratch/bench2.py    # оверхед, edit, большой файл
python _scratch/bench3.py    # чтение: диапазон против целого файла
```

Скрипты и сырые результаты: _scratch/bench.py, _scratch/bench2.py, _scratch/bench3.py, _scratch/bench_results.json.
