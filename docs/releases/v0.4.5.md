## 🔧 Remote Harness MCP v0.4.5

The page you connect a node to Google Gemini on moved, and the steps now name the
connector. Documentation and installer text only: no tool, argument, capability
or payload file changed.

### 🔗 `gemini.google.com/spark/apps` → `gemini.google.com/customize/connectors`

Custom MCP servers now live on the **Connectors** page under **Customize**. Every
installation surface points at the new address:

- `README.md` / `README_RU.md` — the intro link and the quick-start step;
- `install.sh` — both branches (local standalone and gateway + tunnel), both
  languages;
- `install.ps1` — both branches, both languages;
- the visual installer — `$GeminiAppsUrl` in `install-gui.ps1`, plus the
  result-page steps and the button label in `install-gui.strings.json`;
- `install-gui.cmd` — the launcher header and its failure hint name the page as
  well, so the address is still there when the wizard never started;
- `docs/TERMUX.md` (both halves) and `docs/GUI_INSTALLER.md`.

The notes of older releases keep the address they shipped with: they describe
those releases, not this one.

### 🏷️ The connector is named MyDevice

Every set of steps now ends the same way: open the Connectors page, click
**Add connector** (RU: **Добавить коннектор**), name it **MyDevice**, paste the
node's URL into **Server URL** and connect. The visual installer's `res_step2`
string carries the name in both languages, and its button was renamed
**Open Gemini Apps** → **Open Gemini Connectors** to match the page it opens.

### 📦 Package

`remote-harness-mcp@0.4.5`, with `gemini-computer-use@0.4.5` as the alias package.
