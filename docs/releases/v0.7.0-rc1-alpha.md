# Remote Harness MCP 0.7.0-rc1-alpha — no bridge: the node ships its own public endpoint

A pre-release of the architecture change. Until 0.6.x every node needed a relay: a
VPS with a shared domain that terminated TLS and forwarded calls over an outbound
WebSocket tunnel. From 0.7.0 the installer puts the whole stack on the machine and
publishes it with **Tailscale Funnel**; a node has its own HTTPS address and a
bridge is no longer part of the default install.

Tagged `v0.7.0-rc1-alpha`: it installs, updates and serves on this machine, but try
it on one node before rolling it out.

## The architecture change

- **A node is its own public endpoint.** `https://<node>.<tailnet>.ts.net/sse?token=…`
  terminates on the machine itself (Funnel forwards to `127.0.0.1:<port>`). No VPS,
  no shared domain, no DNS, no inbound port on the router, and no second place that
  holds the node's token.
- **The installer defaults to it.** `install.ps1 -Mode standalone -Funnel` and
  `install.sh --mode=funnel` are what the wizard and the shell installer now choose
  first; tunnel mode (`-Mode tunnel`, `--mode=tunnel`) still exists for many nodes
  behind one address.
- **Shares are served by the node**, not built into a bridge path:
  `https://<node>.<tailnet>/<slug>/<file>` instead of `<domain>/<node>/<slug>/<file>`.
- **Tailscale is the only external dependency.** The installer installs the client
  when it is missing, walks through the one-time browser sign-in, and needs Funnel
  allowed for the tailnet (a one-time ACL switch):
  `"nodeAttrs": [{"target": ["autogroup:member"], "attr": ["funnel"]}]`.

## Install, step by step

1. `install-gui.cmd` (wizard, Funnel pre-selected) or the console installer.
2. Tailscale installed and signed in; `BackendState=Running` waited for.
3. `<node>.<tailnet>.ts.net` read from `tailscale status --json`, then `MESH_TOKEN`,
   `MESH_ALLOWED_HOSTS` and `MESH_PUBLIC_URL` written to `standalone.env` (0600).
4. A free port chosen (8096, or the next free one) and autostart registered: the
   `RemoteHarnessMCPService` task (SYSTEM, before logon, restart on failure) or
   `rhm-node.vbs` at logon; the real outcome recorded in `autostart.state.json`.
5. `tailscale funnel --bg --https=443 http://127.0.0.1:<port>` started and verified.
6. The ready link printed and copied: paste it into the Gemini connector.

## `rhm` now describes the installed node

- The menu reads the node's own configuration directory (the service keeps it in
  `%ProgramData%\remote-harness-mcp`), the installer's `autostart.state.json` and
  `standalone.env`, so a Funnel node shows its own `ts.net` address and token
  instead of a bridge URL and an `lk_…` key left by an earlier tunnel install.
- `Status:` is true for a Funnel node as well: with no heartbeat to read (the tunnel
  agent writes it, the standalone server does not), the menu probes the node's
  loopback `/health` and caches the answer for five seconds.
- `rhm --json` additionally reports `endpoint_mode`, `node` and `config_dir`.

## The `rhm` command survives a moved payload

- The Windows shim no longer carries the payload path: it reads `rhm.env` next to
  itself, which every install rewrites. A stale path now prints which file is wrong
  and exits 127 instead of "No module named core.menu".
- The POSIX shim reads `~/.config/remote-harness-mcp/launcher.env` and now actually
  changes into the payload — the previous script ran `python -m core.menu` from
  whatever directory the caller happened to be in.

## Migration from 0.6.x

1. Run the installer again; the wizard already offers Funnel first.
2. Replace the connector URL in Gemini with the new `…ts.net/sse?token=…` link.
3. `agent.env` / `domain.env` from the tunnel era stay on disk as history — a Funnel
   node does not read them and never dials the bridge.
4. The old bridge VPS can be switched off when no tunnel-mode node uses it.

## Known limits of this alpha

- Termux still has no Funnel (Android has no `tailscaled`): the phone keeps using
  tunnel or local-standalone mode.
- Funnel exposes 443, 8443 and 10000 only.
- The link is the credential: whoever holds it can run commands on that machine.
- A pre-release is older than 0.7.0 itself, so a node on this build updates to the
  final release automatically once it ships (set `MESH_UPDATE_CHANNEL=prerelease`
  to keep following pre-releases).
