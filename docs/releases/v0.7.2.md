# Remote Harness MCP v0.7.2 — Windows Installer & In-Place Upgrade Fixes

Patch release fixing Windows visual installer (`.exe`) execution, drive selection, and clean in-place upgrades over an already-installed node.

## Fixes

- **Fixed PowerShell 5.1 `-File` parameter binding crash (`-AddToPath:$true`):** Windows PowerShell 5.1 passed `-AddToPath:$true` as the literal string `"$true"` to `[bool]$AddToPath`, aborting `install.ps1` before startup. `install.ps1` now accepts `[object]$AddToPath = $true` and normalizes both native booleans and string forms (`$true`/`$false`/`true`/`false`/`1`/`0`).
- **Fixed mojibake in Russian installer error output:** `install-gui.ps1` (`Read-TextFileTolerant`) now falls back to the system OEM codepage (CP866 on Russian Windows) when `codePage` is `65001` instead of re-decoding OEM stderr as UTF-8.
- **Fixed drive selection producing `D:\0.7.1`:** `install-gui.ps1` (`Get-DefaultInstallDir`) no longer defaults into the unpacked scratch directory `...\RemoteHarnessMCP\setup\<version>`, and switching drives ignores version-like folder names (`^\d+\.\d+\.\d+`) and `setup` — selecting `D:` now defaults to `D:\RemoteHarnessMCP`.
- **In-place upgrade over existing installations:** added `Get-ExistingInstallDir` to `install-gui.ps1` and `install.ps1` (checking `rhm.env`, `RemoteHarnessMCPService`, and Startup VBS). When an existing installation is detected, the installer targets that exact directory and locks the location fields with a clear notice (`loc_existing_hint`).
- **Graceful stop before upgrade:** added `Stop-ExistingNodeInstances` in `install.ps1` before `Copy-NodePayload` to stop running scheduled tasks (`RemoteHarnessMCPService`) and node/watchdog processes so file overwrites and port binding (`SO_EXCLUSIVEADDRUSE`) succeed cleanly before restarting the updated version.
