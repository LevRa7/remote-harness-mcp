# Протокол верификации: как доказывается «готово»

**Основание:** Superpowers `verification-before-completion`. Железное правило:

> **Никаких заявлений о завершении без свежего доказательства, полученного в этом же прогоне.**

---

## 1. Что считается доказательством

| Уровень | Доказательство | Формат артефакта |
| :--- | :--- | :--- |
| Unit | Вывод pytest с числом passed/failed и кодом возврата | `artifacts/<WBS>/<TEST>.log` + JUnit XML |
| Contract | Прогон схем/конформанса, список кейсов | `artifacts/<WBS>/<TEST>.log` |
| Integration | Лог docker compose/стенда + отчёт теста | лог + `report.json` |
| E2E | Playwright trace, скриншоты, видео | `artifacts/<WBS>/<TEST>/trace.zip` |
| Security | Вывод сканера/теста + severity | лог + `findings.json` |
| Performance | Бенчмарк с p50/p95, профиль | `bench.json` + график |
| Manual | Чек-лист с галочками, скриншот, подпись ревьюера | `artifacts/<WBS>/manual-<date>.md` |
| Migration | Прогон up/down на копии данных | лог + diff схемы |

Артефакт без команды и вывода не считается доказательством.

---

## 2. Обязательный цикл для каждой строки матрицы

```
1. RED    — тест написан и падает; сохранить вывод падения.
2. GREEN  — минимальная реализация; тест проходит; сохранить вывод.
3. REGRESS— прогнать соседние тесты (не только новый).
4. EVIDENCE— артефакты в artifacts/<WBS>/.
5. REVIEW — независимый ревьюер проверяет spec + качество.
6. RECORD — запись в REVIEW_LOG.md с commit, test IDs, путями.
```

Без шага 1 (красный) тест не считается регрессионным.

## 3. Команды (пример)

```bash
# unit / contract
pytest -q tests/test_account_auth.py::test_state_mismatch_rejected -v \
  | tee artifacts/AUTH-02/T-AUTH-02.log
echo "exit=${PIPESTATUS[0]}" >> artifacts/AUTH-02/T-AUTH-02.log

# coverage
pytest -q --cov=account --cov=core --cov-report=term-missing --cov-fail-under=80

# migration
python -m account.migrate --db /tmp/test.db --up
python -m account.migrate --db /tmp/test.db --down 1

# security
bandit -r account core -f json -o artifacts/SEC-09/bandit.json
pip-audit -r requirements-gateway.txt

# team coverage
python tools/check_team_coverage.py --strict
```

## 4. Правила ревьюера

Ревьюер обязан:

- [ ] Прочитать WBS-строку и её критерий приёмки.
- [ ] Проверить, что тест действительно проверяет заявленное, а не тавтологию.
- [ ] Убедиться, что тест падал до реализации (red-green).
- [ ] Прогнать тест самостоятельно (свежий вывод, не доверять отчёту агента).
- [ ] Проверить негативные кейсы и границы.
- [ ] Проверить отсутствие секретов/PII в логах и артефактах.
- [ ] Поставить `APPROVED` или `CHANGES_REQUESTED` в `REVIEW_LOG.md`.

Запрещено: `APPROVED` без запуска, self-approval, «выглядит правильно».

## 5. Гейты

| Гейт | Когда | Кто | Критерий |
| :--- | :--- | :--- | :--- |
| G0 Task | перед стартом задачи | Planner | WBS + тест + владелец + ревьюер |
| G1 Red | перед реализацией | Owner | тест падает, вывод сохранён |
| G2 Green | после реализации | Owner | тест проходит, регресс зелёный |
| G3 Review | после G2 | Reviewer | spec ✅, качество ✅, evidence ✅ |
| G4 Sprint | конец спринта | QA + Planner | все строки спринта закрыты, coverage ≥ 80% |
| G5 Release | перед релизом | QA + SEC + OPS | нет Blocker/Critical, rollback проверен, матрица 100% |

**G5 не может быть пройден, если `python tools/check_team_coverage.py --strict` вернул ненулевой код.**

---

## 6. Политика flaky-тестов

- Flaky-тест не мержится: либо стабилизируется, либо удаляется с записью в `REVIEW_LOG.md`.
- Повторный прогон не считается доказательством, если тест уже был нестабилен.
- Для E2E допускается `retries=1` только с записью причины и владельца.

## 7. Ручные проверки (обязательные)

| ID | Что | Почему вручную |
| :--- | :--- | :--- |
| M-01 | Реальный вход через Google на production-домене | нельзя автоматизировать без секретов |
| M-02 | Автозапуск трея после перезагрузки Windows | требует реальной ОС |
| M-03 | Отзыв агента при живом вызове | гонка в реальном туннеле |
| M-04 | Чтение журнала после ротации/сбоя питания | файловая система |
| M-05 | Кабинет на мобильном браузере | реальный viewport |
| M-06 | Трей при 125%/150% DPI, два монитора | реальное железо |
| M-07 | Поведение при недоступном Google | сеть/прокси |
| M-08 | Обновление поверх старой версии | реальные данные |

Результат каждой ручной проверки — `artifacts/<WBS>/manual-<date>.md` со скриншотом и подписью.

## 8. Запись о завершении (шаблон)

```markdown
## <WBS-ID> — <название>
- Commit: <sha>
- Tests: T-XXX-01, T-XXX-02
- Red: artifacts/<WBS>/red-<date>.log
- Green: artifacts/<WBS>/green-<date>.log
- Regression: <команда, результат>
- Reviewer: <роль/агент> — APPROVED (<date>)
- Ruling: <если было>
```

## 9. Запрещённые формулировки

«Должно работать», «вероятно», «выглядит правильно», «тесты проходили раньше», «агент сказал, что готово», «покрытие и так высокое».

Разрешено: «Команда X, вывод Y, exit 0, артефакт Z».
