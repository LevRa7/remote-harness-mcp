## 1. Вердикт

**NOT_READY** для UI/Desktop-среза: реализацию трея и кабинета начинать нельзя, backend-часть (AUTH/CLM/BE) может стартовать.

Четыре блокера — не «мелкие правки», а нерешённые решения: (1) процессная модель «трей vs узел» и смысл пункта «Выход»; (2) обнаружение control API треем; (3) два конкурирующих сценария привязки на одном маршруте, причём `pair_url` из `gateway.py:954` ведёт на несуществующий маршрут; (4) два независимых автозапуска (трей в HKCU Run, узел из Startup-папки + watchdog каждые 5 минут), из-за которых «Автозапуск: выкл» не значит «выкл».

Три Critical — security/data: код привязки выдаётся без аутентификации; кабинет не защищён от clickjacking (глобальный `CORS *`, нет `frame-ancestors`); CSV-экспорт журнала уязвим к formula injection через редактируемые метки.

Хорошая новость: `WBS.md` (CAB-13/14, TRY-02/06/11, USE-12) и `VERIFICATION_PROTOCOL.md` (M-01…M-08) уже содержат часть нужного; правки — дописать строки и критерии, а не переписывать план. Основные пробелы — состояния, которых нет ни в плане, ни в WBS: `unclaimed`, `agent_down`, `paused`, `update_required`, expired/rate-limited code, degraded-статистика, permission-denied журнала.

### 3.2. Процессная модель трея (Q3): решение до реализации

| Вариант | Админ | Трей/тосты | Обновление | Вердикт |
| :--- | :--- | :--- | :--- | :--- |
| Трей = отдельный процесс, узел = пользовательский процесс (Startup + watchdog) | нет | да | exe нельзя заменить на ходу → нужен handshake версий | **рекомендуется** |
| Windows-служба (Session 0) + трей-клиент | **да** (установка) | служба не может показывать UI | служба обновляется отдельно | отклонено: нарушает «без админа» и W1:299 |
| Трей сам запускает и держит узел | нет | да | проще | отклонено: «Выход» рвёт MCP; конфликт с InstanceLock |

Обязательные детали, которых нет в плане: single instance трея (именованный mutex + активация существующего, иначе двойной клик по ярлыку даёт два значка); трей **присоединяется** к уже запущенному узлу и не спавнит второй (второй агент навсегда ждёт `InstanceLock`, `core/agent.py:541-585`, и выглядит как «мёртвый»); перезапуск = переподключение туннеля, не перезапуск процесса; падение трея → crash-лог и (опция) запись в watchdog; обновление → `/v1/version` (CTL-10) + состояния «обновите трей» / «узел старее»; автозапуск — см. UI-04.

### 3.4. Кабинет: IA и доступность (Q4)

Навигация: **Обзор · Устройства · Агенты · Статистика · Настройки** (+ «Привязать устройство» как действие с Обзора, а не раздел; Privacy — внутри Настроек). Карточка устройства — секции, не вкладки (в Wave 1 всего 4 блока): шапка (имя, ОС/арх, версия, статус, последний контакт), Агенты, Статистика, Опасная зона.

Требования доступности (сверх W1:491): таблицы — `<th scope>`, сортировка кнопкой в заголовке с `aria-sort`, поиск с `<label>`; модалки — focus trap, Esc, возврат фокуса, `role="dialog"` + заголовок; htmx — `aria-busy` на контейнере, `aria-live="polite"` для результата, фокус на заголовок/ошибку после свапа; графики — SVG `role="img"` + `aria-label` + дублирующая таблица (не только цвет, 1.4.1); ошибки — текст + код, `aria-describedby`; skip-link; контраст 4.5:1 / 3:1; tap-target ≥ 24 px (2.5.8); reflow 320 px (1.4.10). Мобильный web: таблицы → карточки, опасные действия — с подтверждением; управление с телефона не запрещать молча.

### 3.5. Журнал (Q5)

Колонки: время (локальное, с TZ; абсолютное в tooltip), агент (ellipsis + title), инструмент, режим, статус (иконка + текст, не только цвет), длительность (`842 ms` / `1.2 s`), байты (KiB/MiB), код ошибки (только при наличии, с расшифровкой). Фильтры: период (сегодня/7/30/90 дней — не больше ретенции), агент, инструмент, статус; сброс. Пагинация — курсор (UI-08), не «последние N». CSV: текущий фильтр, UTF-8 BOM, ISO-8601 UTC + отдельная локальная колонка, quoting, защита от формул (UI-07), имя `usage-<node>-<from>-<to>.csv`, потоковая запись с прогрессом и отменой. Объёмы: 10 МБ × 5 + gzip, ретенция 90 дней; чтение и сводка — потоково, окно не блокируется. Очистка — подтверждение + «очистить всё / старше N дней». Пустые состояния — см. 3.1.

## 6. Чек-лист готовности домена (что проверю лично перед подписанием)

1. Пройдены 10 состояний трея на реальной Win11: иконка, бейдж, tooltip, доступные пункты меню — для каждого есть скриншот.
2. Трей запущен при уже работающем узле: второй агент не создан (в логе нет ожидания `InstanceLock`), состояние `idle` < 5 с.
3. Автозапуск: «выкл» → перезагрузка → нет ни значка, ни узла, ни задачи watchdog; «вкл» → оба поднимаются (M-02).
4. Привязка: просроченный код, 429 после N попыток, чужой аккаунт, код без device token — все четыре дают разные понятные тексты, ни один не раскрывает данные.
5. Журнал на 50 МБ: фильтры, листание без дублей, CSV открывается в Excel и не исполняет `=…`, окно не замирает.
6. Кабинет: axe 0 critical на 6 экранах + NVDA-проход claim/revoke; отзыв агента только с клавиатуры; сессия истекла → логин возвращает на исходную страницу.
7. Контраст измерен (4.5:1 / 3:1) в light, dark, HC; статус читается без цвета.
8. 150% DPI + второй монитор: меню и окно журнала целиком в границах, иконка не мыльная; ru-строки не обрезаны.
9. Чистая VM: SmartScreen/Defender, установка без админа, тост приходит (или fallback), удаление не оставляет записей автозапуска.
10. Язык переключается без перезагрузки на обеих поверхностях, `<html lang>` меняется, ни одна строка не осталась ключом.
